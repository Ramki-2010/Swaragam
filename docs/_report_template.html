Research governance

The project is run as a research record first. Documents have a fixed order of authority, and a result is never promoted past what the experiment shows.

  • Source of truth
    CLAUDE.md, then PROJECT_STATUS.md, the active research plan, phase logs, ADRs, artifacts
  • Frozen decisions
    Hypotheses, thresholds, seeds and datasets change by decision, never by inference
  • Phase gating
    A finished experiment is not approval for the next phase
  • Pre-commit audit
    A repository hook checks staged Python before every commit

Research Review Board

An on-demand panel for hard research questions (ADR-019, ADR-020, ADR-021). Each run assembles six perspectives chosen for that problem and runs them as separate read-only reviewers over a shared evidence brief that they must challenge. The Board is advisory: it cannot advance a phase, authorise an experiment or change code, data or results.

Lesson L-055 records why it is built this way: reviewers reading the same data are not independent evidence, so findings are counted by their underlying source. Each run leaves a minimized, hashed audit package in a local archive that is never committed. A provenance ledger in the repository records that a run happened, by hash. It has no entries yet; earlier runs are not backfilled.
